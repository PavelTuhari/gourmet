# planogram3d — 3D-визуализация планограмм магазина

Python-приложение для трёхмерной визуализации состояния торговых полок:

* **Текущее состояние продаж** — фактическая выкладка на стеллажах,
  раскрашенная теплокартой по остаткам: зелёный — полная выкладка,
  жёлтый/оранжевый — средний и низкий остаток, красный (полупрозрачный) —
  out-of-stock. Глубина стопки товара пропорциональна остатку.
* **Утверждённая планограмма** — согласованная выкладка, раскрашенная по
  поставщикам, сформированная согласно внутреннему регламенту сети и
  контрактам с поставщиками.

Дополнительно приложение проверяет выкладку на соответствие и формирует
отчёт о нарушениях по четырём группам:

| Группа | Что проверяется |
|---|---|
| Внутренний регламент | тяжёлые товары только на нижних полках, товар помещается в просвет полки, выкладка не выходит за край и не пересекается |
| Контракты с поставщиками | минимальная доля полки (по фронту), обязательные SKU с минимумом фейсингов, размещение на уровне глаз |
| Соответствие планограмме | отсутствующие позиции, лишние позиции, расхождение числа фейсингов с утверждёнными |
| Продажи и остатки | out-of-stock, низкая заполненность, запас меньше дневных продаж |

## Установка и запуск

```bash
pip install -r planogram3d/requirements.txt   # plotly
python -m planogram3d                          # из корня репозитория
```

Либо как самостоятельный pip-пакет (появится и консольная команда
`planogram3d`):

```bash
pip install ./planogram3d
planogram3d --no-browser
```

Результат — интерактивный HTML-отчёт `planogram_report.html` (открывается
в браузере автоматически): 3D-сцена с кнопками переключения режимов,
вращением/зумом мышью и всплывающими карточками по каждому товару
(SKU, поставщик, фейсинги, остаток, скорость продаж), а под сценой —
таблица нарушений.

Опции:

```bash
python -m planogram3d -o отчёт.html   # путь к выходному файлу
python -m planogram3d --seed 7        # другие демо-данные о продажах
python -m planogram3d --no-browser    # не открывать браузер
```

## Веб-режим: сеть магазинов на карте города

Локальный сервер с эмуляцией работающей торговой сети в духе игровых
симуляторов магазинов: точки сети показаны на **реальной карте Твери**
(данные OpenStreetMap: улицы, здания, Волга, парки) с переключаемым
**2D/3D**-видом — в 3D здания города выдавливаются по реальной этажности.

```bash
pip install -r planogram3d/requirements.txt   # plotly + flask
python -m planogram3d.webapp                   # http://127.0.0.1:8050
```

Что происходит на карте:

* фоновый тикер ускоренно проигрывает торговый день (1 с = 10 мин):
  продажи по скорости `SalesInfo.sales_rate`, начисление выручки,
  out-of-stock и пополнения полок;
* маркеры магазинов «как в игре»: рейтинг звёздами по выручке, цвет
  статуса (зелёный/жёлтый/красный), всплывающие «+N ₽» при продажах;
* панель сети: выручка, продажи, пустые полки и живая лента событий;
* **мониторинг Zabbix**: на маркере каждого магазина — бейдж с числом
  активных проблем (цвет — по максимальной severity, шкала Zabbix), в
  карточке — список проблем с давностью; без реального сервера работает
  встроенная эмуляция торгового оборудования (кассы, холодильники,
  эквайринг, ИБП);
* клик по магазину — карточка KPI, а кнопка «Войти в магазин» делает
  игровой переход: камера подлетает к зданию, «дверь» — и вы внутри,
  перед реальной интерактивной **3D-планограммой** магазина с шапкой
  KPI/Zabbix и кнопкой «Назад на карту»;
* **логистический центр (опционально)** — РЦ-буфер между поставщиками
  и магазинами: при out-of-stock магазин заказывает товар в РЦ,
  грузовики 🚚 едут по карте города, склад РЦ списывается и сам
  перезаказывается у поставщиков; при пустом складе РЦ магазин получает
  прямую (более долгую) поставку. Карточка РЦ — остатки, SKU ниже точки
  заказа, рейсы. Отключается переменной `PLANOGRAM_DC=0`;
* внутри магазина — опциональная вкладка **«🎮 Симуляция зала»**:
  изометрический торговый зал в духе игровых симуляторов, где
  покупатели входят (события видеонаблюдения), ходят к реальным
  стеллажам планограммы, берут товар, взвешивают на весах и оплачивают
  на кассах или в зоне касс самообслуживания (СКО); рядом — KPI зала
  (посетители, чеки, выручка касс, доля СКО, взвешивания) и живая
  лента событий. Работает от **тестового потока** (встроенный эмулятор)
  или от **реального потока** данных касс/весов/CCTV, принимаемого по
  `POST /api/instore/<id>/ingest` — при активном реальном потоке
  эмулятор замолкает (см. docs/INTEGRATION.md).

  На схеме зала дополнительно отображаются:

  * **очереди у касс и СКО** в реальном времени (по позициям покупателей
    либо по событиям `queue` от видеоаналитики);
  * **оценка числа покупателей** по датчикам входа/выхода: вошло минус
    вышло, за вычетом стоящих в очередях — остальные равномерно случайно
    распределяются по свободному полу зала (полупрозрачные «призраки»,
    отключается галочкой);
  * **ТСД** (терминалы сбора данных) с позиционированием по BLE-маякам
    в торговой зоне (±0.5–1 м) и LoRa-датчикам на остальной площади
    (±2–3.5 м) — с кругом точности, источником и зарядом батареи;
  * **холодильные витрины** с телеметрией: температура, дверца,
    компрессор; выход за уставку — тревога (принимается и реальная
    телеметрия событием `fridge`);
  * **учёт расходников**: чековая лента каждой кассы и СКО, лента
    этикеток весов, кульки для овощей — расход при чеках и
    взвешиваниях, события «вызван сотрудник»/«лента заменена»;
  * **зоны скоропортящихся продуктов** (молочная группа, холодильники)
    особо выделены пунктирной рамкой «❄ скоропорт»;

* третья вкладка внутри магазина — **«🎓 Тренажёр»**: полноценная
  игра-обучение кассиров и команды магазина в жанре тайм-менеджмента
  (в духе Supermarket Mania). Игрок — сотрудник магазина: пополняет
  полки со склада, обслуживает покупателей на кассе, убирает разливы,
  меняет чековую ленту и чинит холодильники. У покупателей — терпение
  ❤ (уходят злыми — падает репутация), товары и цены — из реальной
  планограммы магазина. Три смены-уровня с целями по выручке,
  нарастающей сложностью, туториалом на первой смене, очередью действий
  из двух кликов, звёздами за результат и обучающим разбором ошибок в
  конце смены (`/store/<id>/game`);

* раздел **«🛵 Интернет-заказы и доставка»** (`/delivery`) — полный
  сценарий работы магазина с онлайн-заказами: сборка товаров по
  планограмме (new → сборка → упакован), **группировка заказов по
  маршрутам** (2–4 адреса, ближайший сосед от магазина),
  **диаграмма Ганта** план/факт по каждому плечу маршрута (дорога и
  вручение, линия «сейчас», подсветка опозданий), **мониторинг
  доставки на карте города в реальном времени** по GPS-координатам из
  курьерского приложения (`POST /api/delivery/gps`; без телеметрии —
  эмуляция движения), **чек в момент вручения** с печатной формой
  (`/receipt/<id>`) и два варианта курьерского приложения: обычный
  **Android** (фискализация облачной кассой, электронный чек
  покупателю) и смарт-терминал **SmartOne с фискальным накопителем на
  борту** (печать бумажного чека на месте, работает офлайн);

* **интеграция с Roblox**: члены команды регистрируются в тренажёре
  (имя + ник Roblox), за пройденные смены и кейсы начисляются баллы и
  бейджи, ведётся лидерборд и лента поощрений; при настроенных ключах
  Open Cloud (`ROBLOX_API_KEY`, `ROBLOX_UNIVERSE_ID`) баллы пишутся в
  DataStore опыта, а поощрения объявляются в игре через
  MessagingService. Конвертор `planogram3d.robloxkit` генерирует
  place-файлы `.rbxlx` для Roblox Studio: торговый зал с реальной
  планограммой и Luau-тренажёром (готовые демо — в `robloxkit/demo/`)
  и обзорную сцену сети города.

Подключение реального Zabbix (иначе — эмуляция):

```bash
export ZABBIX_URL=https://zabbix.example.com
export ZABBIX_TOKEN=<api-токен>
export ZABBIX_HOSTS="st17=store-17.local,st03=store-03.local"  # id → хост
python -m planogram3d.webapp
```

Карта полностью автономна: MapLibre GL и выгрузка OSM лежат в
`webapp/static/`, интернет для работы не нужен. Пересобрать карту под
другой город можно скриптом `webapp/tools/build_map_data.py` из свежих
выгрузок Overpass API.

## Структура пакета

Вся переиспользуемая функциональность выделена в ядро
`planogram3d.core` — встраиваемую библиотеку без зависимостей, кроме
`plotly`; демо-приложение — тонкая обёртка над ним.

| Модуль | Назначение |
|---|---|
| `core/models.py` | модель данных: магазин, стеллажи, полки, товары, поставщики, контракты, планограммы, продажи |
| `core/rules.py` | движок проверки соответствия (регламент, контракты, планограмма, продажи) + пользовательские проверки |
| `core/viz.py` | построение 3D-сцены (Plotly Mesh3d) |
| `core/report.py` | отчёты: консольный, HTML-блок, автономная HTML-страница |
| `sample_data.py` | демонстрационный магазин с намеренными отклонениями выкладки |
| `app.py` | демонстрационное CLI поверх ядра |
| `webapp/network.py` | эмуляция сети магазинов: тикер продаж, OOS, логистический центр, события |
| `webapp/zabbix.py` | интеграция с Zabbix API (активные проблемы по магазинам) + эмулятор |
| `webapp/instore.py` | симуляция торгового зала: покупатели, кассы, СКО, весы, CCTV + приём реального потока |
| `webapp/server.py` | Flask-сервер: карта сети, API состояния, 3D-планограммы магазинов |
| `webapp/templates/map.html` | карта города (MapLibre GL): 2D/3D, игровые маркеры, панель сети |
| `webapp/templates/game.html` | игра-тренажёр персонала: смены, покупатели, касса, склад, события |
| `webapp/roblox.py` | команда Roblox: регистрация, баллы, бейджи, Open Cloud / эмуляция |
| `webapp/delivery.py` | интернет-заказы: сборка, маршруты, GPS-мониторинг, фискальные чеки |
| `robloxkit/` | конвертор сцен в формат Roblox (.rbxlx) + Luau-скрипты тренажёра |
| `webapp/tools/build_map_data.py` | сборка GeoJSON карты города из выгрузок Overpass API (OSM) |

## Подключение своих данных

Чтобы визуализировать реальный магазин, соберите объект
`planogram3d.core.Store` из своих источников (учётная система, БД,
выгрузки) по образцу `sample_data.build_demo_store()` и передайте его в
`build_figure(store)` и `check_compliance(store)` — подробности и
готовые примеры в [docs/INTEGRATION.md](docs/INTEGRATION.md).
