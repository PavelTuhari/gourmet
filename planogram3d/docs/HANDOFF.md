состояние, архитектурные решения с причинами, известные грабли,
рецепты тестирования, бэклог. Файл читается человеком и ИИ-ассистентом;

машину, куда вытянута ветка.*

## 3. Архитектурные решения и их причины

1. **Один объект `Store` — вся интеграция.** Любые данные (ERP, CSV,
   БД) заходят только через него; ядро не знает об источниках.
2. **Эмулятор и реальный источник — один интерфейс.** Zabbix, события
   зала (`/api/instore/<id>/ingest`), GPS доставки, Roblox Open Cloud:
   везде провайдер выбирается по env-переменным, реальный поток
   глушит эмулятор по таймауту (60 с зал, 45 с GPS). Это позволило
   демонстрировать всё с первого дня.
3. **Evolve-on-poll вместо фоновых потоков** в instore/delivery/
   multigame: мир «доигрывается» при каждом запросе состояния (dt
   ограничен). Исключение — network: фоновый тикер-поток (2 с) и
   таймскейл 1 с = 10 мин. Не плодить новых потоков без нужды.
4. **Командная смена авторитарна на сервере**, клиенты тонкие; роль не
   знает, кто её исполняет (human/bot/api) — это фундамент роадмапа
   ИИ-замещения (docs/ROADMAP_AI_WORKFORCE.md).
5. **Карта полностью автономна**: MapLibre и GeoJSON (Кишинёв для
   розницы, вся Молдова для топливного контура) лежат в репозитории;
   интернет для работы не нужен. Пересборка под другой город/страну —
   `webapp/tools/build_map_data.py` / `build_moldova_map.py` из
   выгрузок Overpass.
6. **Отчёт планограммы** по умолчанию `include_plotlyjs=True`
   (автономный файл ~5 МБ); для веб-отдачи есть `"cdn"` (~250 КБ).
7. **RBXLX пишем сами** (без зависимостей): свойства сериализуются
   вручную, токены Enum.Material захардкожены в `rbxlx.py`.
8. **Мини-Markdown свой** (`mdview.py`), а не библиотека — ноль
   зависимостей; поддержано: заголовки, списки, таблицы, код, картинки,
   склейка мягких переносов.

## 4. Известные грабли (сэкономят часы)

1. **`pkill -f planogram3d` убивает сам вызывающий bash** (паттерн
   совпадает с командной строкой). Убивать сервер только через PID:
   `kill $(lsof -t -iTCP:8050 -sTCP:LISTEN)`. На macOS `fuser -k`
   отсутствует вовсе (нет такой утилиты) — `fuser` годится только в
   контейнере/Linux; на macOS всегда `lsof -t -iTCP:<port>
   -sTCP:LISTEN` + `kill`.
2. **Playwright не может кликнуть анимированный маркер** (元 element
   is not stable из-за pulse-анимации) — кликать через
   `page.evaluate("...click()")`.
3. **pywebview не ставится системным pip на Ubuntu** (патченый
   setuptools ломает сборку proxy_tools: `install_layout`). В venv
   ставится нормально — лаунчеры и установщик работают через venv.
4. **PyGObject (gi) привязан к версии питона**: в контейнере `_gi` был
   собран под 3.12, а дефолтный python — кастомный 3.11 → venv строить
   от `/usr/bin/python3.12 --system-site-packages`. На Mac эта проблема
   отсутствует (pywebview использует pyobjc).
5. **Overpass API часто отдаёт 504/обрывы** — делить запрос на части
   (roads/buildings/nature), ретраи с паузами. Зеркало
   `overpass.kumi.systems` отдаёт 500 — рабочее зеркало —
   `overpass-api.de` (подробности и дробление городских запросов —
   §4.12). Готовые данные уже в репо — без нужды не пересобирать.
6. **LibreOffice в облачном контейнере не открывает pptx вообще**
   («source file could not be loaded» даже на минимальном файле) —
   визуальную проверку pptx делать нечем; валидируется скриптом
   validate.py и python-pptx, финальную проверку делать локально в
   PowerPoint/Keynote.
7. **mdview._unwrap**: исходники MD с жёсткими переносами склеиваются
   в абзацы; была ошибка «каждая строка — отдельный `<p>`». Если
   добавляете новую Markdown-конструкцию — проверяйте взаимодействие
   со склейкой (код-фенсы исключены из склейки).
8. **`price_for()` использует `hash(sku)`** — из-за рандомизации хэша
   Python цены МЕНЯЮТСЯ между перезапусками процесса. Для демо
   терпимо, для стабильных тестов — заменить на
   `zlib.crc32(sku.encode())` (см. бэклог).
9. **Эмодзи в headless Chromium** рендерятся упрощённо (моно-глифы) —
   это нормально для скриншотов, на живых машинах вид богаче.
10. **Порт 8050 занят после падения** — снова `kill $(lsof -t
    -iTCP:8050 -sTCP:LISTEN)` (см. §4.1); сервер запускать через
    `setsid nohup ... &`, иначе умрёт с шеллом.
11. **Один тик эмуляции сети продаёт помногу** — если менять
    `TIME_SCALE`/скорости, перепроверять экономику смен тренажёра
    (цели подобраны под текущие константы).
12. **Зеркало Overpass `overpass.kumi.systems` отдаёт 500** — рабочее
    зеркало `overpass-api.de`. Национальный запрос (трассы всей
    Молдовы) проходит одним куском без проблем, а вот городской запрос
    по дорогам и зданиям Кишинёва даёт 504 (сервер не успевает) и
    требует дробления: дороги — по классам (`motorway`/`trunk`
    отдельно от `primary` и т.д.), здания — по квадрантам города; между
    частями — паузы, иначе частые повторные запросы возвращают 429
    (rate limit).
13. **Выгрузка целого города в GeoJSON не помещается в бюджет автономной
    карты** — полный Кишинёв (все дороги и здания без отсева) даёт
    44 171 объект и 12 МБ, против 2551 объекта и 664 КБ у тверской
    карты (для сравнения масштаба). Лечится обрезкой охвата до центра
    города и отбором только крупнейших зданий — итоговая
    `chisinau_map.geojson` уложилась в 6928 объектов и 2,1 МБ.
14. **В MapLibre слой `symbol` с `text-field` без заданного в стиле
    `glyphs` рушит рендер всей карты**, а не только текстовых подписей:
    карта показывает пустой холст (ни дорог, ни воды, ни маркеров), и
    ошибка в консоли (`text-field requires a style "glyphs" property`)
    легко теряется среди прочих логов. Задавать внешний `glyphs`
    нельзя — это сетевой сервер шрифтов, а карта обязана быть
    автономной. Решение, применённое на карте топливного контура:
    подписи городов заменены слоем `circle` (точки без текста) — без
    `text-field` слой `symbol` не нужен вовсе.

## 5. Рецепты тестирования (проверено в этой сессии)

* **Smoke всей системы**: поднять сервер, `curl /api/state`,
  `/api/instore/st17/state`, `/api/delivery/state`,
  `/api/roblox/team`, `/api/fuel/state` — все должны отдавать 200 и
  живые числа; поле `source` в `/api/fuel/state` — `"emulation"` без
  `ARTGRANIT_URL`, `"artgranit"` при живой и доступной ERP.
* **Скриншоты экранов** — Playwright + системный Chromium
  (`executable_path='/opt/pw-browsers/chromium'` в контейнере; локально
  обычный `playwright install`). Двухкратный `device_scale_factor` даёт
  чёткие снимки для доков.
* **Игровые сценарии** прогоняются через `window.game`-хуки:
  `game.clickHall(x, y)` в соло, REST-действия в командной смене.
  Быстрые прогоны: `?time=30&level=2` у соло-тренажёра.
* **Линк-чекер презентации**: собрать `href` со страницы `/presentation`
  регуляркой и обойти curl'ом — все внутренние ссылки должны быть 200.
* **Установщик** тестировать в чистом `HOME` (подменой env), с
  `PLANOGRAM3D_NO_GUI=1`.
* **Внешний ИИ-агент**: `python -m planogram3d.webapp.tools.demo_bot
  --role cashier --room тест --start --seconds 60` — должен набрать
  баллы больше нуля.

## 6. Переменные окружения (все опциональны)

| Переменная | Назначение |
|---|---|
| `PLANOGRAM_DC=0` | отключить логистический центр |
| `ZABBIX_URL`, `ZABBIX_TOKEN`, `ZABBIX_HOSTS` | реальный Zabbix вместо эмулятора |
| `ARTGRANIT_URL` | адрес ERP Artgranit (например `http://127.0.0.1:3003`); не задана — топливный контур (`peco_fuel.py`) полностью автономен, ни одного сетевого вызова |
| `ARTGRANIT_TIMEOUT=3.0` | таймаут одного GET-запроса к Artgranit, с |
| `ARTGRANIT_POLL_INTERVAL=5.0` | не опрашивать Artgranit чаще этого интервала (evolve-on-poll, без потока) |
| `REAL_ARTGRANIT_TIMEOUT=20.0` | окно свежести реальных данных после последнего успешного опроса — истекло, контур сам возвращается к эмуляции (образец — `REAL_GPS_TIMEOUT` в `delivery.py`) |
| `ROBLOX_API_KEY`, `ROBLOX_UNIVERSE_ID` | реальный Open Cloud (DataStore + MessagingService) |
| `PLANOGRAM_TEAM_FILE` | путь файла-реестра команды (default `planogram_team.json` в cwd) |
| `PLANOGRAM3D_NO_GUI=1` | desktop.py: только сервер, без окна (для CI) |
