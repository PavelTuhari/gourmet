# План: визуализация автозаказа топлива (Проект B)

> Исполнителю: план ведётся по задачам, каждая заканчивается работающим и
> проверенным запуском результатом. Шаги отмечаются `- [ ]`.

**Цель:** инициация автозаказа топлива в Artgranit (`POST /api/plg/fuel/autoorder`)
становится видна в planogram3d как живая карта: бензовозы едут от нефтебазы
к реальным АЗС Молдовы по трассам, у каждой станции — ИИ-табло прибытия.

**Архитектура:** новый контур `webapp/peco_fuel.py` по образцу `network.py`:
эмулятор работает всегда, реальные данные Artgranit подмешиваются опросом и
глушат эмулятор по таймауту — тот же приём, что уже применён к Zabbix и GPS
доставки. Карта Молдовы автономна (свой GeoJSON в репозитории), маршруты —
вторым экземпляром `RoadNet` по национальному графу трасс. Прогноз прибытия —
существующий `eta_ai` с новым классом транспорта `tanker`.

**Стек:** Python 3, Flask, MapLibre, ванильный JS. Без новых зависимостей.

## Глобальные ограничения

- **Автономность.** Карта и данные лежат в репозитории; интернет для работы
  не нужен (инвариант проекта, `docs/HANDOFF.md` §3.5). Overpass вызывается
  только инструментом сборки, вручную, не в рантайме.
- **У каждого внешнего контура — эмулятор с интерфейсом реального
  источника.** Реальный поток глушит эмулятор по таймауту (§3.2 HANDOFF).
- **Evolve-on-poll**, без новых фоновых потоков (§3.3 HANDOFF). Исключение
  уже существует ровно одно — тикер `network`, новых не заводить.
- **Artgranit только читается.** Никаких записей в его API из planogram3d.
  Опрос — `GET`, инициацию автозаказа выполняет оператор в Artgranit.
- **Недоступность Artgranit не должна ронять экран**: любая сетевая ошибка
  переводит контур в эмуляцию, а не в стектрейс.
- **Размерный бюджет карты**: `tver_map.geojson` — 664 КБ. Национальная
  карта не должна превышать ~2.5 МБ, иначе страница будет долго стартовать.
- Ветка `claude/3d-sales-visualization-fsbyam`, репозиторий
  `/Users/pt/Projects.AI/gourmet-claude-3d-sales-visualization-fsbyam/planogram3d`.

## Задача 2: Контур топлива — эмулятор

**Файлы:** создать `webapp/peco_fuel.py`; править `webapp/eta_ai.py`

**Интерфейсы (на них опираются задачи 3–5):**
- `FuelNetwork(map_path: Path)` — контур; `state() -> dict` (evolve-on-poll)
- `state()` возвращает:
  `{"now": float, "source": "emulation"|"artgranit", "depot": {...},
    "stations": [...], "trips": [...], "runs": [...], "events": [...]}`
- станция: `{id, code, name, lat, lon, region, capacity_l, current_l,
  fill_pct, days_to_dry, is_low}`
- рейс: `{id, driver, liters, load_pct, depart, eta, progress, lat, lon,
  path: [[lon,lat], ...], stops: [{station_id, name, liters, eta_ts}]}`

- [ ] **Шаг 0: Починить широтную привязку метрики `roadnet`**

Найдено при сборке карты (Задача 1): `webapp/roadnet.py` держит масштаб
долготы модульной константой под широту Твери —
`_KX = 111320 * cos(56.86°)`. На широте Молдовы (~47°) это **занижает
расстояния по долготе на 20%**, а по факту маршрут Кишинёв→Бэлць вышел
121.5 км против 133.6 км геодезических. Пока это не исправлено, длины
плеч и, следовательно, ETA молдавского контура систематически врут.

Сделать масштаб принадлежностью экземпляра `RoadNet` (например,
необязательный параметр опорной широты у конструктора) **со значением
по умолчанию, сохраняющим текущее поведение тверского контура**.
Модульные `cumulative()` и `point_along()` использует `webapp/delivery.py`
для Твери — если меняешь их сигнатуру, новый параметр обязан быть
необязательным и по умолчанию давать ровно прежний результат.

Проверка: маршрут Кишинёв→Бэлць по молдавской карте должен дать длину,
близкую к геодезической (≈134 км, расхождение в пределах нескольких
процентов), а тверской маршрут — не измениться. Прогнать оба:

```bash
cd <repo>
python3 - <<'EOF'
from pathlib import Path
from planogram3d.webapp.roadnet import RoadNet, get_roadnet
md = RoadNet(Path("planogram3d/webapp/static/data/moldova_map.geojson"), ...)
_, m = md.route(28.8575, 47.0105, 27.9185, 47.7615)
print("Молдова, Кишинёв->Бэлць, км:", round(m / 1000, 1))   # ожидание ~130-140
_, t = get_roadnet().route(35.8842, 56.8478, 35.9045, 56.8570)
print("Тверь, РЦ->магазин, м:", round(t))                    # значение как было
EOF
```

## Задача 3: Реальный поток из Artgranit

**Файлы:** править `webapp/peco_fuel.py`

**Интерфейсы:** `state()["source"]` становится `"artgranit"`, когда
свежие данные получены, и возвращается в `"emulation"` по таймауту.

- [ ] **Шаг 1: Клиент**

Опрос `GET {ARTGRANIT_URL}/api/plg/fuel/stations` и `/trips` (формы
ответов — в разделе «Что уже выяснено»). Требования:

* адрес и таймаут — из переменных окружения, со значениями по
  умолчанию; переменные задокументировать в HANDOFF §6;
* **только чтение**, никаких POST в Artgranit;
* любая ошибка (сеть, таймаут, не-200, битый JSON) не поднимается
  наверх, а оставляет контур в эмуляции;
* опрос не чаще, чем раз в несколько секунд, и **не в отдельном
  потоке** — вписать в evolve-on-poll: пришло время, дёрнули, положили
  в кэш;
* реальные данные глушат эмулятор по таймауту (взять за образец
  `REAL_GPS_TIMEOUT` из `webapp/delivery.py`), а не навсегда.

Даты Artgranit приходят строками RFC 1123 — разбирать
`email.utils.parsedate_to_datetime`, не изобретая парсер.

Рейсы Artgranit могут не иметь GPS (`last_lat`/`last_lon` = `null`) —
в этом случае положение бензовоза считается по маршруту и плановому
времени, как в эмуляции; при наличии координат — берутся они.

## Критерии приёмки

1. `/fuel` открывается, показывает 46 АЗС Молдовы, нефтебазу и рейсы.
2. Бензовоз движется по полилинии трассы, а не по прямой.
3. Клик по АЗС открывает ИИ-табло прибытия с ±σ.
4. При поднятом Artgranit источник — `artgranit` и данные реальные;
   при недоступном — `emulation`, экран продолжает работать.
5. Инициация автозаказа в Artgranit приводит к появлению рейса в
   planogram3d (или задокументировано, почему не удалось проверить).
6. Карта автономна: работает при отключённом интернете.
7. Тверской контур (`/`, `/delivery`, магазины) не затронут.
