# Задача 2: Контур топлива — эмулятор. Отчёт

## Шаг 0: широтная привязка `roadnet`

`RoadNet.__init__` получил необязательный параметр `ref_lat` (по
умолчанию `56.86` — широта Твери), масштаб долготы (`kx`) стал
атрибутом экземпляра вместо модульной константы. Все внутренние методы
(`snap`, `route`, дубликаты в `route`) и функция `cumulative()` теперь
принимают/используют этот масштаб явно (у `cumulative` — необязательный
параметр `kx`, по умолчанию тверской, для обратной совместимости с
`delivery.py`, который вызывает `cumulative(path)` без аргументов).
`point_along()` не трогал(ся) — не считает расстояний, менять было
нечего.

Проверка (буквально по заданию):

```
Молдова, Кишинёв->Бэлць, км: 134.3   (ref_lat=47.0)
Тверь, РЦ->магазин, м: 2666
```

Тверское значение (2666 м) идентично значению **до** правки (проверено
через `git stash`/пересчёт на неизменённом коде) — тверской контур не
затронут ни на метр. Молдавское расстояние (134.3 км) близко к
геодезическому (~134 км) — до правки (масштаб под 56.86°) было бы
занижено на ~20% (около 121.5 км, как и зафиксировано в плане).

## Шаг 1: априорная скорость танкера

`webapp/eta_ai.py`, `_PRIOR_SPEED["tanker"] = 2200.0` (м/с в
эмуляции — величина условная, как и у существующих классов `truck`/
`courier`, "ускоренное время"). Обоснование в комментарии рядом с
константой: самое длинное штатное плечо сети (Кишинёв→Бэлць, 134.3 км)
должно укладываться в порядок минуты ускоренного времени —
134 300 / 2200 ≈ 61 с, то же соотношение сжатия, что уже применено к
truck (45 м/с) и courier (22 м/с) для городских плеч.

## Шаг 2: эмулятор `webapp/peco_fuel.py`

Создан `FuelNetwork` — evolve-on-poll (весь мир доигрывается внутри
`state()`, шаг `dt` ограничен `MAX_DT=5.0` с, фонового потока нет).

Ключевые решения:

* **Станции** — 46 шт., реальные координаты и остатки сняты с живого
  Artgranit `GET /api/plg/fuel/stations?lang=ru` (20.08.2026,
  `station_id, station_code, station_name, lat, lon, region,
  capacity_l, current_l, daily_rate_l, tank_count`), зашиты как
  Python-список `STATIONS` — контур остаётся автономным без Задачи 3.
* **Нефтебаза** — «Нефтебаза Сынжера» (депо реальных рейсов Artgranit,
  `depot_id=1`). **Допущение**: ни `/stations`, ни `/trips`, ни
  `/runs` не отдают координаты депо — использованы реальные координаты
  посёлка Сынжера под Кишинёвом (46.9503, 28.8189), отмечено
  комментарием в коде.
* **Маршрут второй экземпляр `RoadNet`** — `FuelNetwork.net =
  RoadNet(moldova_map.geojson, ref_lat=47.0)`, тверской синглтон
  `get_roadnet()` не используется и не создаётся.
* **Расход топлива** — станции списывают `daily_rate_l` в сжатом
  времени (`TIME_SCALE=2400`, аналог `network.TIME_SCALE`), иначе
  суточный расход в 4–9 тыс. л был бы незаметен за время прогона.
* **Порог автозаказа** — `REORDER_FRACTION=0.42` (доля ёмкости);
  подобран так, чтобы демонстрация не зависела только от скорости
  расхода: 4 из 46 станций уже ниже порога на реальных стартовых
  остатках Artgranit, что и обеспечило появление рейса в первом же
  цикле проверки автозаказа теста шага 3.
* **Диспетчеризация** — до 4 станций в рейсе, объезд ближайшим соседом
  от нефтебазы (тот же приём, что `delivery._build_routes` для
  курьеров), маршрут строится плечо за плечом через `RoadNet.route` и
  склеивается в одну полилинию `path`; на каждую станцию отгружается
  не больше объёма одной секции бензовоза
  (`TANKER_CAPACITY_L/MAX_STOPS_PER_TRIP` = 30000/4 = 7500 л) — иначе
  при первой же проверке рейс "вёз" бы физически невозможные объёмы
  (первая версия без этого ограничения отгружала 224 669 л одним
  рейсом — исправлено).
* **Обучение ИИ-табло** — на каждой завершённой остановке
  `get_predictor().observe("tanker", leg_m, elapsed)`; предиктор общий
  с остальными контурами (`eta_ai.get_predictor()`), как и было
  указано в задании.
* **Не трогались**: `network.py`, `instore.py`, `multigame.py`,
  `templates/map.html`, `templates/delivery.html`, `server.py`.

## Допущения и открытые вопросы

1. Координаты нефтебазы «Сынжера» — не из Artgranit (там их нет),
   взяты как реальные координаты посёлка Сынжера под Кишинёвом.
2. Порог автозаказа (`REORDER_FRACTION=0.42`) и объём секции бензовоза
   (7500 л) — эвристики автора эмулятора, не взяты из Artgranit
   (там есть `below_alarm_count`/`dry_risk_count`, но не пороговые
   доли по агрегированному `capacity_l/current_l`, которые я
   использую); при подключении реального опроса в Задаче 3 их можно
   будет свести к алармам Artgranit, если потребуется точнее совпадать
   с ERP-логикой.
3. `days_to_dry` считается по агрегированному `current_l/daily_rate_l`,
   не по помарочной раскладке резервуаров (Artgranit хранит остатки
   по грейдам топлива отдельно) — упрощение в рамках интерфейса,
   заданного планом (`{capacity_l, current_l, days_to_dry, ...}` без
   разбивки по грейдам).
