# Отчёт: Задача 1 — Национальная карта Молдовы

Ветка `claude/3d-sales-visualization-fsbyam`, коммит `3910f98c`.

## Что сделано

Созданы два файла, ровно как требовало задание:

- `webapp/tools/build_moldova_map.py` — сборщик, по образцу
  `build_map_data.py` (те же аргументы: три входных пути + путь выхода,
  тот же способ проставлять `properties.kind`, статистика в конце).
- `webapp/static/data/moldova_map.geojson` — собранная карта.

Тверская карта и `build_map_data.py` не тронуты.

## Шаг 1: сборщик

Прочитан `webapp/tools/build_map_data.py` как образец. Написан
`build_moldova_map.py` с фильтрацией:

- трассы: `motorway`/`trunk` → `road_major`, `primary` → `road`;
  координаты округляются до 4 знаков, повторы подряд схлопываются;
- вода: фильтр по площади bbox `MIN_WATER_BBOX_DEG2 = 0.0003` (град.²);
- города: `place=city|town` с непустым `name`, `rank` из тега `place`.

### Первая сборка — не влезла в бюджет

Первый прогон (только округление координат, без упрощения линий) дал
**3532 КБ** — почти вдвое больше бюджета в 2.5 МБ. Основной вклад —
координаты трасс: 88 715 точек в `road` + 37 517 в `road_major` (вода —
всего 14 030, города — 98).

**Решение:** добавлено упрощение линий трасс алгоритмом Дугласа —
Пойкера с допуском `ROAD_SIMPLIFY_TOLERANCE_DEG = 0.0008°`
(≈60–70 м в широтах Молдовы — заметно меньше расстояния между
станциями PECO).

Наивное применение DP к каждой линии независимо сломало граф
маршрутизации (см. «Шаг 3» ниже) — алгоритм переписан так, чтобы
никогда не выбрасывать точки-перекрёстки (координаты, встречающиеся
более чем в одной линии трассы): сначала по всем линиям строится
частотный словарь координат, точки с частотой >1 помечаются
защищёнными, DP-упрощение запускается отдельно на каждом отрезке между
такими точками, само упрощение их никогда не трогает.

## Шаг 3: проверка графа маршрутизацией

Первая попытка (упрощение без защиты перекрёстков) дала связный граф,
но с ложным разрывом: точка-стык двух линий трасс случайно попадала под
DP-упрощение и выбрасывалась как «незначительное» отклонение внутри
одной линии, хотя как раз через неё проходил кратчайший путь. Маршрут
Кишинёв→Бэлць в этой версии находился (394 узла — граф не рассыпался
до двух точек), но шёл кружным путём: 195.6 км по метрике `RoadNet`
(219 км по геодезической метрике) — заметно выше ожидаемых 120–160 км.
Диагностика: сравнение с картой без округления/упрощения (134 км,
в норме) и с картой после округления координат без упрощения (122.7 км,
тоже в норме) локализовало причину именно в упрощении линий.

После фикса (упрощение с защитой точек-перекрёстков):

```
$ python3 - <<'EOF'
from planogram3d.webapp.roadnet import RoadNet
from pathlib import Path
net = RoadNet(Path("planogram3d/webapp/static/data/moldova_map.geojson"))
path, m = net.route(28.8575, 47.0105, 27.9185, 47.7615)
print("узлов в пути:", len(path), "длина, км:", round(m / 1000, 1))
EOF
узлов в графе (крупнейшая компонента): 13142
узлов в пути: 451 длина, км: 121.5
```

Дополнительно посчитана длина того же пути по геодезической формуле
(на случай неточности `_KX` в `RoadNet`, зашитой под широту Твери
56.86° — для Молдовы 47° точный коэффициент отличается): **133.6 км**.
Оба числа — метрика `RoadNet` (121.5 км) и геодезическая (133.6 км) —
попадают в ожидаемый диапазон 120–160 км. Путь состоит из 451 узла —
не прямая (100 км по прямой) и не два конца.

## Пороги фильтрации — что и почему

- `MIN_WATER_BBOX_DEG2 = 0.0003` — площадь bbox в градусах². Дала 68
  водных объектов из 10 872 (Днестр, Прут, водохранилища — крупные
  вытянутые объекты с большим bbox; мелкие пруды отсеялись). Порог
  подобран перебором по требованию «порядка сотни объектов» —
  68 в этот порядок укладывается.
- `ROAD_SIMPLIFY_TOLERANCE_DEG = 0.0008°` (≈60-70 м) — снизил вклад
  трасс в размер файла в разы (с 3532 КБ до итоговых 1809 КБ при том
  же округлении координат), связность графа сохранена явной защитой
  точек-перекрёстков.
- Округление координат до 4 знаков (≈11 м) — как предписано заданием.

## Отклонения от задания

Нет прямых отклонений от текста задания. Единственное дополнение —
защита точек-перекрёстков при упрощении линий, которую задание не
описывало явно (там говорилось только про округление координат и
схлопывание повторов), но без неё бюджет и пригодность графа для
маршрутизации одновременно не достигались: без упрощения файл не лезет
в бюджет (3.5 МБ), с наивным упрощением бюджет соблюдён, но граф рвётся
на стыках и маршрут удлиняется почти вдвое.

## Сомнения

- `RoadNet._KX` в `webapp/roadnet.py` — модульная константа, зашитая
  под широту Твери (`cos(56.86°)`), не под широту точки. Для Молдовы
  (47°) собственная метрика класса занижает метровые расстояния
  относительно геодезических (121.5 км против 133.6 км реальных на
  этом же пути — расхождение ~9%). Задание прямо запрещает менять
  класс («править класс не нужно»), поэтому не трогал; для задачи 1
  расхождение не критично (оба числа в ожидаемом диапазоне), но в
  задачах 2–3 (эмулятор рейсов, ETA бензовозов) эта неточность будет
  сказываться на прогнозах времени в пути — стоит иметь в виду при
  калибровке `eta_ai` для класса `tanker`.
- Порог по воде (68 объектов) не проверялся визуально на карте (нет
  GUI-сверки, что это именно Днестр/Прут/водохранилища, а не какие-то
  другие крупные полигоны) — доверился только площади bbox, как
  предписывало задание.
